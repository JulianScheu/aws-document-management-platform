# Project progress — 2026-11-15

## Applied scenario
The demonstration follows an industrial record through its lifecycle: a synthetic maintenance or quality report is uploaded, assigned a processing status, stored independently of the app, and retrieved during an operational review. The scenario reflects hands-on familiarity with production-line fault analysis, sensor checks, documentation and handovers. No actual employer or customer records are used.

## Summary
From architecture/Terraform drafts to a running AWS DocuWorks proof of concept in eu-central-1. This is an interim project milestone, not a production release or final DCI submission.

## Confirmed implementation
- AWS personal account and budget alert prepared; Frankfurt region selected.
- Terraform provider initialized and configuration validated; `terraform apply` finished with **18 added, 0 changed, 0 destroyed**.
- Deployed VPC `10.20.0.0/16`, public subnet `10.20.1.0/24`, Internet Gateway, route table, security group without inbound access, EC2 `t3.micro`, IAM/SSM role and private versioned S3 bucket.
- EC2 instance: `i-063506cdd8af56a5c`; separate 8 GB data EBS: `vol-0769ddaa52c3ce1ec`.
- XFS data volume mounted to `/data`; UUID added to `/etc/fstab`; automatic mounting verified after EC2 reboot.
- Deployed Flask application using Python 3.12 and Gunicorn; managed by `docuworks.service` with systemd.
- SQLite metadata persists at `/data/docuworks/docuworks.db`; document contents stored in private S3.
- Browser access from Mac via AWS SSM port forwarding (`localhost:8765` to instance `127.0.0.1:5000`), without opening an inbound HTTP port.

## Gaps and technical debt
- EBS mount, Python packages and systemd service were configured manually. Re-provisioning a replacement instance still needs automated bootstrap/IaC.
- No automated snapshot schedule or restoration workflow yet.
- CloudWatch monitoring and central logs are not yet configured.
- Staff authentication, TLS/HTTPS and a supported multi-user application entrypoint are missing. Current access is only a restricted proof-of-concept tunnel.
- Security negative test, AWS Well-Architected/cost assessment, final AWS-icon diagrams and presentation remain open.
- SQLite on one EBS volume plus one EC2 instance cannot provide high availability.
